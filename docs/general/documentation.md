# Drunir Collection technical documentation

## Platform and installation

Minecraft 1.21.1, Java 21, and NeoForge 21.1.259 are the development baseline. The mod accepts subsequent NeoForge 21.1 releases. Install the same JAR on the client and server. No additional mod dependencies are required.

The mod identifier is `landofdrunir`. Existing Land of Drunir builds use the same identifier and must not be installed together with this collection. This is an initial creative content build, not a complete port of the original mod.

## Available content

The Drunir Blocks tab contains 154 placeable decorative blocks. The five creative building colors are `peach_grass_block` (`grass1.png`), `coral_grass_block` (`grass3.png`), `violet_grass_block` (`grass.png`), `mint_grass_block` (`grass4.png`), and `lime_grass_block` (`grass5.png`). These decorative full cubes use their original supplied image on every face and the same position based horizontal texture rotations as other natural surfaces. They have no natural generation, spreading, or biome tint. Logs rotate on placement, hollow logs have open collision shapes, plants use transparent crossed models, leaves use transparent cube models, and doors and trapdoors use standard interactive Minecraft behavior. Decorative sand does not fall. Saplings are decorative and do not grow trees. The blocks drop themselves when broken in survival, with one item per door.

Thirty three natural and decorative blocks use four equally weighted horizontal model rotations, at 0, 90, 180, and 270 degrees. This includes the three original grass surfaces, the five additional decorative grass colors, both sands, both raw sandstones, Blueschist, raw Larimar, the four ores, both leaf blocks, and all flowers, bushes, and saplings. The existing artwork is preserved. Rotation around the vertical axis keeps grass and sandstone tops facing upward. Directional logs, hollow logs, doors, trapdoors, pillars, and crafted blocks retain their original orientation rules.

This uses Minecraft's standard position based block model selection. Each position keeps the same choice when chunks or resources load again. The world seed does not directly choose the rotation, and the effect does not animate or change saved block states. In the content catalog, `random_y_rotation: true` enables the four variants for a non-directional block. The resource validator checks the rotation angles, equal weights, model targets, and unlocked texture coordinates.

The Drunir Items tab contains 84 items, including materials, food, tools, swords, lance artwork, and three wearable armor sets. Tools use standard vanilla tiers, and lances currently use sword behavior. Food is edible. Armor uses the original Drunite, Galeon, and Plasmite texture sheets. Goblin Drip is a wearable cosmetic chest accessory using the extra sheet, with no armor protection. The supplied extra leggings sheet is transparent. Living armor has inventory artwork only and remains ordinary preview items until worn textures are supplied. Boat, sign, hanging sign, and candle inventory artwork is present as items; these items do not yet place functional vehicles, signs, or candles.

The Drunir Creatures tab displays only the Deer Spawn Egg and uses it as its icon. All 11 creature types and their spawn eggs remain registered, so saved entities and command access keep working. They use the original model geometry and textures, with original walk animations where supplied. All creatures use basic passive movement. They do not reproduce the original combat, trading, breeding, or natural spawning behavior. The Magmafiend fireball is registered as a separate projectile with its original model and texture and can be created with `/summon landofdrunir:magmafiend_fireball`.

The Drunir Texture Gallery contains a separate obtainable sample item for each of the 296 source PNG files. Samples expose alternate icons, large entity texture sheets, and armor layers as flat images. Trim palette previews apply each original palette to a helmet trim sprite, preserving normal block atlas mipmapping. A sample is an inventory image for inspecting artwork. Trim palettes do not yet add smithing materials. Gallery identifiers follow `landofdrunir:texture/<original texture path without .png>`. For example, `/give @s landofdrunir:texture/entity/boar` gives the boar texture sheet.

Content is obtained from creative tabs or `/give` and `/summon`. This build does not add crafting recipes, custom ore generation, another dimension, progression, or the original mod's special abilities.

## Yellow Tree Forest

The biome identifier is `landofdrunir:yellow_tree_forest`. The former `landofdrunir:golden_birch_island` definition remains available only to decode old saved biome palettes. On loading an existing chunk, its old forest entries are replaced by the new key and the chunk is marked for saving. Other biome entries and block data are preserved. The island anchor filename remains unchanged. One connected forest island is anchored in each Overworld save, approximately 1,000 blocks across with an irregular coast, beaches, a surrounding ocean belt, and a smooth transition into ordinary terrain. The interior has `landofdrunir:yellow_grass_block` over regular Minecraft dirt. Trees use vanilla birch logs and `landofdrunir:yellow_birch_leaves`. The grove uses irregular tree sites with dense outer woodland that thins progressively toward the center. A 10 block radius around the saved center excludes all trunks, branches, and canopy leaves. Trees whose crowns would overhang this clearing are skipped. A fully jittered four block candidate lattice is filtered by local priority and distance, rather than accepting rows of tree sites. Trunk clearance increases from approximately 4 blocks near the edge to approximately 12 blocks centrally, with smooth local variation creating thicker groves and clearings. Placement probability also fades toward the central opening. Rounded and branching birches retain the two established tree styles, with small, medium, and tall variants, varied widths, familiar layered crowns, curved stems, forks, and umbrellas. Trunk heights range from approximately 5 to 22 blocks before extra lift for nearby slopes. Branching forms become more frequent inward. Canopies begin above three clear blocks over the dirt. Before placement, the feature checks the highest dirt beneath each canopy column in a bounded vertical window and extends the trunk if needed, so nearby slopes do not fill walking space with leaves. Every branch top is covered, and generated leaves have a valid distance of 1 through 6 from birch logs. They retain normal decay after players remove their supporting logs. Sun Hollies replace other naturally generated ground plants and emit light level 4. The forest, shore, and protected waters have empty mob lists and carver lists. Natural and spawner generated mobs are blocked within 768 blocks of the saved center; commands, spawn eggs, dispensers, buckets, breeding, and conversion remain available for intentional placement. Existing mobs can still walk into the region.

`/drunir island` displays its saved center coordinates without requiring operator permission. The normal `/locate biome landofdrunir:yellow_tree_forest` command also recognizes the biome when it is within that command's search range. A new world's first candidate is roughly 4,000 to 6,200 blocks from the coordinate origin. In existing worlds, occupied region files cause the initial search to move outward until it finds an unexplored area. The search is bounded to 128 candidates and refuses generation if all are occupied. It does not replace existing terrain.

The location and shape seed are saved once in the Overworld's `data/landofdrunir_golden_island.dat`, schema 1. Later loads reuse that record rather than selecting another island. Preserve this file with the world. An unreadable or unsupported existing record prevents startup rather than creating a replacement island. Restore a valid backup to recover such a record. Deleting it is not a supported relocation method.

Generation applies only to the standard, Large Biomes, and Amplified Overworld noise generators. Nether, End, superflat worlds, and other generator types are unaffected. No alternate world preset is needed. The forest biome is selected only within its single saved boundary. The beach and submerged sandy shelf use `landofdrunir:golden_birch_shore`, and the surrounding water uses `landofdrunir:golden_birch_waters`. The shore continues 96 blocks past the nominal coast, mostly below sea level. The forest boundary is 32 blocks inside the nominal coast, reducing exposed beach. A continuous cubic height profile meets the land and seabed at the waterline with the same slope, rather than flattening at sea level. Small height variations and additional coast harmonics break up uniform terraces. The island's density function operates only in its bounded region, blending out completely at 1,024 blocks from its center. This is not a repeating climate entry.

Narrow runtime hooks connect the saved boundary to biome sampling, possible biome enumeration, noise density, and surface rules. Both final density and preliminary surface density use the island profile so the aquifer fills the surrounding ocean correctly. Noise wrappers are runtime objects; original generator settings remain serializable and unchanged. `IslandWorldgen` separates location loading, context assembly, and surface rules. The context is bound before initial spawn generation and cleared when the Overworld unloads. Vanilla ore placement remains. Lakes, geodes, monster rooms, springs, cave vegetation, ordinary flowers, and grass patches are omitted. The density profile fills the underground mass, and a narrow carver hook prevents neighboring biome carvers from cutting into protected chunks. A structure hook rejects generated structures whose bounds intersect the protected area. This does not remove features or entities from existing chunks.

Biome, configured tree, placed tree, shoreline, and boulder templates live in `tools/worldgen`. The normal resource generator emits them into the mod data pack. The yellow grass and shoreline blocks are included in the dirt block tag so vanilla tree placement accepts it. `GoldenGroveFeature` finds the ground using the heightmap that ignores leaves, produces regular dirt under trunks, and places the shared `GoldenTreeShape` geometry after checking its complete footprint. Crowns may overlap existing foliage, and leaves preserve existing logs so neighboring trees can form a canopy without erasing trunks. `GroveLayout` assigns sites independently of chunk generation order. The former four configured tree identifiers remain available for compatibility, while natural placement uses `landofdrunir:golden_grove`.

### Shoreline and vegetation

New island terrain has a 24 block transition centered on the forest boundary. `landofdrunir:golden_shore_sand` stores a `tone` from 0 through 7. The outer edge uses ordinary sand color. Moving inland warms the sand toward gold and gradually increases coverage by fragments of the existing yellow grass texture. The original PNG files are unchanged. Colors and model fragments depend on the stored tone, so clients do not need the world seed or a custom network message.

`ShorePalette` owns the transition width, color progression, and stable position dithering. `ShoreBlendFeature` paints only the current chunk's exposed sand or yellow grass during local modification, before tree placement. It does not modify existing loaded terrain. `LandscapeColors` registers the client color handler. The shoreline model generator in `tools/landscape_resources.py` owns the grass fragment coverage.

The island and shore omit vanilla grass patch features. Short grass, tall grass, and green grass surfaces are not part of their generation. Sun Hollies replace other ground flowers and plants, and natural wildlife spawns are blocked. Other Overworld biomes retain normal vegetation. Existing generated chunks keep their previous terrain and plants; use a new test world or newly generated chunks to inspect landscape changes.

### Modular boulders

The Drunir Boulders tab contains 60 pieces: three materials, five sizes, and four distinct forms. Materials are Blueschist, Brown Sandstone, and Dark Brown Sandstone. Forms are Rounded, Crag, Flat, and Cluster. Tiny pieces are 2 pixels high, Small 4, Medium 8, Big 12, and Huge 16. Width grows with height. Huge pieces occupy one block cell; combine pieces vertically and horizontally to build formations spanning many blocks. All pieces reuse existing textures. Models use two or three broad cuboid masses with coarse stair-like cuts, without sloped polygon faces or a narrow central column surrounded by small pellets. Brown sandstone and dark brown sandstone use their original fine-grained top textures on the whole rock.

For example, `/give @s landofdrunir:blueschist_huge_crag_boulder` supplies a Huge Blueschist Crag. The identifier pattern is `<material>_<size>_<form>_boulder`.

Right click a boulder with another piece of the same material to add its height. The existing lower form and facing remain. When the total exceeds one block, the lower rock fills its cell and the remaining height becomes a new piece directly above, using the held form. Overflow requires replaceable space, placement permission, world bounds, and clearance from entities. A blocked upper space leaves both the rock and held item unchanged. Sneak to place a separate piece instead. Once a cell is full, ordinary placement continues on its top or sides. Pieces can be waterlogged, rotated, and mirrored.

Breaking a modular rock returns its height as Tiny pieces of the same material and form. One layer equals one Tiny piece, so combining and breaking rocks preserves their amount. Creative placement follows normal unlimited creative inventory behavior. The original three slab boulder identifiers, models, and stacked drops remain available for saved-world compatibility.

`assets/landofdrunir/boulders.json` defines materials, size layer counts and natural placement weights, widths, and normalized form boxes. `BoulderCatalog` supplies shared geometry transforms for Java collision, while `tools/boulder_resources.py` emits matching models, all 60 item models and translations, loot tables, and weighted natural placement states from the same definitions. Eight stored layer counts support intermediate heights created by stacking. The three placed block identifiers end in `_boulder_piece`; the state stores `layers`, `form`, `facing`, and `waterlogged`. Inventory choices use fixed size/form defaults without adding 60 block types.

Adjacent modular pieces of the same material merge their shared edges automatically. Horizontal joins fill only the common height, including four block junctions, while exposed sides keep a coarse stepped outline. Connection bands are four pixels high, with one two-pixel inset at the exposed top edge. Vertical joins close the footprint between a full lower piece and the piece above it. Empty half-block air gaps are not bridged. Different materials and the original slab boulders remain separate. Removing a neighbor restores the standalone outline. This uses existing block states and also updates formations in existing worlds without regenerating terrain.

`BoulderJoin` describes the nearby pieces and computes the connecting geometry. `BoulderShapes` reads only the eight adjacent horizontal cells and the blocks directly above and below, matching only the same placed block identifier. Its bounded geometry cache is shared by selection and collision. The block uses dynamic shapes so collision does not retain its standalone shape after neighbors change. Lighting uses only the stored state and standalone occlusion shape, because the lighting worker must not request server chunks. Full-height pieces block light and provide stone ambient shading; lower pieces retain shape-based light occlusion. Matching full-height stacks keep a continuous side profile instead of repeating a ledge at every cell.

The client uses the NeoForge `connected_boulder` geometry loader and a model data snapshot of those same neighbors. `BoulderSurface` extracts only the exposed faces of the box union and merges adjacent coplanar rectangles. `ConnectedBoulderModel` bakes those surfaces with consistent block-space texture coordinates, normal directional culling for cell-boundary faces, and a bounded cache per material model. Resource reloads replace the model instances and their texture caches. Inventory models retain the standalone forms. Boulder joining requires no block entity, custom packet, persisted connection property, or additional mixin.

`BoulderPieceBlock` supplies the connected selection and collision shapes. `BoulderPieceItem` handles placement and bounded two-cell overflow through the normal block item flow, preserving standard placement feedback, item consumption, and client synchronization. `BoulderStackPlan` accounts for layer conservation. `CollectionBoulders` registers the inventory choices. Existing slab rocks continue using the earlier `boulder_shape` catalog field and `BoulderBlock`.

Natural forest placement makes two attempts per chunk, favors Blueschist and smaller sizes, and includes all four forms and five sizes. Existing generated chunks keep their old rocks. New pieces can be used immediately for player builds in existing worlds.

## Source layout and initialization

`DrunirCollection` separates armor, block, item, gallery, and tab registration into focused methods. It reads the packaged `assets/landofdrunir/content.json` catalog once during initialization. It registers armor materials, blocks, items, and creative tabs through NeoForge deferred registers. `CollectionCreatures` registers creature types, attributes, spawn eggs, and the fireball type. Common initialization has no client class references.

`client/DrunirClient` handles client model layers and renderers. `DrunirGeometry` retains the original model geometry, and `DrunirAnimations` contains the six walk definitions used by those renderers. The four goblin variants share one geometry builder while retaining separate entity identifiers and textures. Walk loop durations include their final keyframes. Creatures without a supplied walk cycle use an explicit static pose, and unknown model or animation names are rejected. `HollowLogBlock` supplies collision and selection shapes for each log axis. `DecorativePlantBlock` provides the block codec for crossed decorative plants.

Original PNG files are under `src/main/resources/assets/landofdrunir/textures`. The content catalog is authoritative for identifiers and resource generation. Hollow log model JSON files are hand maintained under the main resources; their parent is the standard block parent.

## Building and editing

Use Java 21 and the checked in Gradle Wrapper:

```sh
./gradlew build
```

The output is `build/libs/drunir-collection-neoforge-1.21.1-0.1.0.jar`. The build requires Python 3 for resource generation and validation. Set `JAVA_HOME` to your Java 21 installation when another Java version is the system default.

`./gradlew generateResources` runs `tools/generate_resources.py`, which writes models, blockstates, language entries, block loot tables, and block tags into `src/generated/resources`. Do not edit those outputs directly. Update the content catalog or generator and regenerate instead. After successful generation, obsolete JSON files in that generated directory are removed automatically. Output paths must stay inside the generated directory, and existing symlinks are rejected before generation begins. Keep hand maintained resources in `src/main/resources`.

`./gradlew validateResources` checks JSON syntax, model references, custom texture references, parent cycles, duplicate identifiers, PNG headers, complete gallery coverage, registry identifier collisions, known catalog kinds, and inline face texture aliases. It is included in `build`. The metadata version is expanded from Gradle’s `mod_version`, so the JAR and loader metadata use the same version. Java compilation checks the pinned Minecraft and NeoForge APIs. Client model tests bake every creature and verify that walk channels target existing parts with finite, ordered keyframes within the loop duration. Resource tool tests reject invalid catalog entries, cross category identifier collisions, unresolved texture aliases, path traversal, and output symlinks. JUnit tests cover stable seed selection, occupied terrain avoidance, one connected island boundary, dry forest terrain, continuous shore slopes, submerged sand coverage, the ocean belt, and the outer transition. Boulder tests check all form/height/rotation bounds, distinct silhouettes, 60 unique choices, conservation of height when stacking, matching shared faces, solid four-piece junctions, vertical joins, restoration of standalone shapes, 128 rotation-independent pointed formations with supported solid interiors, and exposed surface area without internal faces. Shore palette tests cover endpoints, ordered tones, and bounded colors. Resource validation also checks boulder geometry, stacked models, shoreline states, and the absence of grass patch features. Runtime model baking and visual appearance must also be checked with a matching client when assets or renderers change.

`./gradlew runClient` starts a development client. `./gradlew runServer` starts a dedicated development server. Accept the Minecraft EULA in the server runtime before starting it. Use disposable worlds when changing registry content during development.

### Shore atmosphere and shipwrecks

The three island biomes share muted sage fog, subdued sky colors, and deep teal water. The shore and surrounding waters reuse vanilla warm ocean coral reefs, mixed short and tall seagrass, and sea pickles. Noise based coral placement forms irregular reef patches with sandy gaps. These aquatic features run in vanilla order before the sunken ship feature, which preserves the wrecks and chest contents. The dry forest keeps its Sun Holly cover and has no aquatic feature entries. The sanctuary mob ban remains in force, including fish and drowned. Reef and seagrass generation requires new chunks. Fog begins across the island reef waters and warm beach. It covers the entire sandy transition, then fades over 16 blocks after full yellow grass begins. Translucent, slow moving mist banks drift above the water and warm sand. Fog resets when changing worlds and preserves underwater, lava, and short distance status effect fog. Particle settings can reduce visible mist. Sun Holly light uses the existing texture without adding an animated material or shader dependency.

Six seed stable wreck sites lie around the submerged sandy shelf. `IslandWreckSites` derives them from the persisted island shape seed. `SunkenShipFeature` places rotated vanilla shipwreck templates at those sites, settles them into the seabed, ignores template air to preserve water, and assigns the standard supply, treasure, and map chest loot tables. Wrecks are features rather than ordinary structure starts, making them the explicit exception to the island structure ban. They appear only as their new chunks generate. Existing worlds keep their saved anchor and previously generated terrain.

### Natural rock outcrops

`IslandBoulderFeature` attempts a small spike once per six forest chunks on average, before trees are placed. It rejects steep ground, fluids, tree trunks, and occupied cells before placing anything. `BoulderFormation` selects one of 128 deterministic small spike profiles, then a horizontal rotation. Profiles have a three by three block maximum footprint, one narrow central tip, and low irregular shoulders. One foundation layer is buried, leaving approximately 1.5 to 2.5 blocks of exposed height. A fixed seed builds the profile bank once, rejecting duplicate silhouettes under all four rotations; runtime placement selects a profile. Every body column is solid, with only exposed caps using vanilla slabs or stairs. All columns connect to the buried foundation. Standard solid blocks and vanilla partial shapes supply occlusion, collision, and ambient shading. After placement, neighboring stair shapes resolve into normal inner and outer corners. Small loose boulders retain their separate placement feature.

The formation uses the existing full Blueschist and sandstone blocks plus matching `<material>_rock_slab` and `<material>_rock_stairs` blocks. These six building blocks appear in the Blocks tab, reuse original stone textures, and support normal placement, stair corners, waterlogging, and double slab drops. `tools/landscape_resources.py` emits their vanilla models and blockstates. Each formation chooses one material for its core and edges. Existing modular boulder identifiers, layer quantities, connected geometry, and drops remain compatible.

### Lost navigation

Compasses rotate continuously while their holder or item frame is within the island sanctuary, including the reef, beach, and clear forest interior. Ordinary, lodestone, and recovery compasses resume their normal behavior outside it or in another dimension. The client-only `CompassVeilMixin` changes the compass model angle without changing item data or its saved target.

Inside the same area, the F3 XYZ, Block, Chunk, Chunk-relative, and targeted block or fluid coordinate lines drift together. This is a visual effect through NeoForge's debug text event. Player positions, movement, chunk loading, commands, saved data, and server coordinates remain real. Other debug information is retained.

The server sends a bounded `landofdrunir:island_boundary` snapshot on login and data pack reload, using play-to-client protocol version 1. The payload contains an enabled flag, center X and Z, and shape seed, at most 19 payload bytes. There are no client-to-server messages or per-tick network updates. The default main-thread handler stores the boundary against the receiving connection. Logout clears it; dimension checks disable effects outside the Overworld. Clients and servers must install the same build. `IslandVeil` shares the actual saved island shape with fog and navigation effects.
